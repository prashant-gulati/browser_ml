## What Was Built

### 1. `package.json`
Introduced npm tooling. Key points:
- `"type": "module"` — matches the HTML's `<script type="module">`
- Vitest + jsdom + Playwright as devDependencies
- TF.js + MediaPipe model packages listed as **devDependencies for `npm audit` only** (not imported into tests) — covers all 7 CDN libraries
- `npm install --legacy-peer-deps` required because TF.js model packages have conflicting peer dep versions between themselves

### 2. `vitest.config.js`
- `environment: 'jsdom'`
- `include: ['tests/unit/**']` — critical to exclude Playwright `.spec.js` files from Vitest's glob
- Coverage via `@vitest/coverage-v8`

### 3. `src/detection-utils.js` (new)
Pure functions extracted from `browser-ml.html`'s `<script type="module">` for testability. The core constraint: every drawing/DOM function now takes its dependencies as **explicit parameters** rather than closing over module-level variables.

| Extracted function | Key change |
|---|---|
| `drawBox`, `drawDot`, `drawConnections` | `ctx` added as first param |
| `drawFaceDetections`, `drawObjects`, `drawPoses`, `drawHands` | Already took `(ctx, canvas, data)` — internal calls updated |
| `drawSegmentation` | `createCanvas` factory injected (default: `document.createElement('canvas')`) |
| `drawFaceMesh` | `FaceLandmarkerRef` added as param |
| `setStatus` | `statusEl` added as first param |
| `syncCanvasSize` | `canvas`, `video` added as params |
| `mapBlazeFacePred`, `mapMediaPipeDet` | Extracted from inline boot functions |

### 4. `browser-ml.html` — changes
- Added `import { ... } from './src/detection-utils.js'` at top of `<script type="module">`
- `setStatus` replaced with thin wrapper: `const setStatus = (msg, err) => _setStatus(statusEl, msg, err)`
- `syncCanvasSize()` call updated to `syncCanvasSize(canvas, video)`
- All local function definitions removed (now in module)
- `bootBlazeFace` / `bootMediaPipe` use `mapBlazeFacePred` / `mapMediaPipeDet`
- `bootFaceLandmarks` assigns lambda: `(ctx, canvas, result) => drawFaceMesh(ctx, canvas, result, FaceLandmarkerRef)`
- `maskCanvas` module-level variable removed (managed internally in `drawSegmentation`)

- `drawDot` — arc coordinates, default radius

- `classColor` — HSL output, memoization
- `drawObjects`, `drawPoses`, `drawHands` — count strings, filtering

Canvas mock in `vitest.setup.js`: minimal stub with `vi.fn()` for all 2D context methods. jsdom has no canvas implementation.

### 7. `k6/load-test.js`
Tests the static hosting layer (not in-browser ML):
- Ramp: 10 VUs → 50 VUs → hold 2 min → ramp down
- Thresholds: `http_req_failed < 1%`, `p(95) < 2s`
- Checks: status 200, body contains "Detection Playground" + all 7 backend names, under 100KB
- k6 is a standalone binary, not in package.json
- Not in CI — run manually post-deploy: `k6 run --env BASE_URL=https://your-app.netlify.app k6/load-test.js`

### 8. Monitoring — `browser-ml.html` additions
**Sentry SDK** (`browser.sentry-cdn.com/7.119.0/bundle.min.js`) + **Web Vitals** (`unpkg.com/web-vitals@3.5.2`) — both with SRI hashes, both loaded in `<head>`.

Sentry is a **no-op unless `window.SENTRY_DSN` is set at deploy time**. For Netlify, inject via `_headers` or Edge Function. Sentry DSNs are intentionally public (origin-restricted in Sentry dashboard).

Instrumentation:
- `Sentry.init()` + Web Vitals reporting (CLS, FID, LCP, FCP, TTFB) → on bootstrap
- Camera permission granted/denied → `addBreadcrumb`
- Backend selected → `addBreadcrumb`
- Model load → `sentrySpan('model.load.<backend>', ...)` + `captureMessage('Model ready', { loadMs })`
- Inference errors → `captureException`
- Inference latency → rolling 30-frame buffer, `setMeasurement('inference.avg_ms')` every 90 frames

### 9. Security — `browser-ml.html` additions
**CSP meta tag** (first `<meta>` in `<head>`):
```
default-src 'none';
script-src  'self' 'unsafe-inline' cdn.jsdelivr.net browser.sentry-cdn.com unpkg.com;
connect-src 'self' *.ingest.sentry.io storage.googleapis.com cdn.jsdelivr.net;
media-src   'self';
img-src     'self' data:;
style-src   'self' 'unsafe-inline';
worker-src  blob:;
```

Known limitations documented in comments:
- `'unsafe-inline'` unavoidable (JS is in an inline `<script type="module">`)
- `worker-src blob:` required for MediaPipe + BodyPix WASM workers
- MediaPipe `import()` cannot have SRI (browser limitation for dynamic ESM imports)

**SRI on `loadScript()`** via `SCRIPT_SRI` map — all 6 TF.js CDN scripts covered. Hashes computed at implementation time via `curl -s <URL> | openssl dgst -sha384 -binary | openssl base64 -A`.

### 10. `.github/workflows/ci.yml`
Three parallel jobs:
- **unit-tests** — `npm ci --legacy-peer-deps && npm test` + coverage artifact
- **e2e-tests** — Playwright Chromium only + `playwright-report` artifact on failure
- **security-audit** — `npm audit --audit-level=high` (fails on high/critical CVEs in pinned CDN deps)

Repo guidance file with commands, architecture overview, runtime flow diagram, backend table, testing quirks, and SRI update instructions.

## Known Gaps / Future Work

- **SRI for MediaPipe**: `import()` (dynamic ESM) doesn't support `integrity` in current browsers. Would require vendoring the WASM files locally.
- **`'unsafe-inline'` CSP**: Can be eliminated by extracting the inline `<script type="module">` to an external `.js` file, or by using nonce-based CSP via a Netlify Edge Function.
- **k6 in CI**: Add a `workflow_dispatch`-triggered job that runs post-deploy against the live URL.
- **Sentry DSN injection**: Netlify `_headers` or Edge Function needed. GitHub Pages has no dynamic header injection — would need a build step.
- **E2E model load tests**: Current E2E tests only check the loading state. Full model-load tests (asserting "Ready" status) would require ~30s timeouts and reliable CDN access in CI — omitted for now.
